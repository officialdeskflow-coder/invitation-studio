# Add a template

```
npm run new:template -- spring-blush --from royal-maroon-gold
npm run new:client  -- spring-demo --template spring-blush
npm run build -- spring-demo && npm test
```
The new template starts as a copy, so it builds on day one. Change it step by step, rebuilding often.

## Worked example
`templates/sage-garden` was built this way and shares nothing visual with `royal-maroon-gold`: new tokens in `base.css`, new components, its own `svg/edges.json`, vector art generated by `engine/tools/sage-garden-art.py`, and a different opening (`components/gate/`). Read its `gate.js` and `hero.js` to see how a template plugs into `K.finish` and `K.hero.reveal`.

## What to change
1. **Look**: `base.css` (colours/type tokens at `:root`), then each `components/*/*.css`. Keep the tone of each section (`dark`/`light`) in `template.json` in sync with the real background, because edges depend on it.
2. **Art**: replace `assets/florals/*.webp`, `assets/venue/mandap.webp`, `svg/` (seal, branch, torn paths, symbols). Transparent WebP, about 440 px wide, under 100 KB each.
3. **Fonts**: put woff2 files in `engine/shared/fonts/` and list them in `template.json → fonts`. Self-host only (never link Google Fonts: it adds a network dependency and a layout shift).
4. **Wording**: `defaults.json`. Clients override only what they need.
5. **Motion**: `components/*/*.js`. Keep the ids/classes in the contract (docs/ARCHITECTURE.md). Reuse `K` helpers so calm mode and failsafes keep working.
6. **Opening**: `components/gate/` is the signature. Anything that hides content must be undone by a timeline, and `K.finish`/`K.plain` must still be able to open the page.

## Contract reminders
- `gate.js` must set `K.finish` and call `K.hero.reveal(timeline, at)`; `hero.js` defines `K.hero.reveal`.
- Keep the config keys (`couple`, `date`, `hero`, `invite`, `countdown`, `schedule`, `venue`, `gallery`, `rsvp`, `closing`, `features`, `music`, `sections`, `seo`) so clients can switch templates. Add new keys with defaults.
- Elements the core manages must keep their classes: `.rv`, `.hi`, `.flr`, `.cl`.
- The CSS cascade across components matters: when a component rule such as `.clo>*{position:relative}` meets a shared rule (`.flr{position:absolute}`), give the specific one a higher-specificity selector.

## Rules that keep a new template safe
- Read `docs/MOTION-RULES.md` first.
- Never remove `.rv`/`.hi` from content you animate (the failsafe watches them).
- Hidden start states are set by JavaScript (`gsap.set`) or under `.js` in CSS, never in plain CSS, so no-JS stays readable.
- Photos get `width`, `height` and `alt` (the test enforces it) and an `aspect-ratio` rule that is not overridden by the HTML `height` attribute (use `height:auto`).
- CSS that depends on order must live in the same file, or be commented.

## Prove it
`npm test` (structure), `python engine/qa/qa.py READY-TO-UPLOAD/<name>/index.html` (animation QA), `python engine/qa/parity.py old.html new.html` (when refactoring an existing design and you want pixel-exact layout), then the real-phone checklist.
